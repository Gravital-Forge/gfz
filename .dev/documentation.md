# documentation binding

Kept documentation is exactly these living documents, each path from the repository root:

- `README.md`, the user's document: what `gfz` does, how to install and configure it, and the
  accounts it creates.
- `docs/plugins.md`, the plugin author's document: the manifest, template values, settings, step
  naming, and the `examples/hello` walkthrough.

Update a kept document whenever a change affects what it describes. The enumeration is the rule, and
the set is closed. Only the operator adds a kept document; never add one as a default home for new
prose.

Everything else resolves to the workspace root: the root `documentation` topic, the `implementation`
skill for a work item's working documents, and the workspace root `CLAUDE.md`'s Writing section for
the style every kept document must satisfy.
